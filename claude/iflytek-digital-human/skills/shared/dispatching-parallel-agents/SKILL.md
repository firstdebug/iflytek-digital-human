# Dispatching Parallel Agents

## When to Use

- 手头有 **N 个彼此独立** 的任务，各自能单独完成、互不依赖对方的产出
- 典型场景：
  - 并行调研多个子系统 / 多个文件（只读）
  - 并行实现多个互不相干的模块
  - 三端（web / android / ios）各自独立的检查或实现
  - 对一批文件做同类独立处理

## 何时 **不能** 并行（硬规则）

- **有依赖**：任务 B 需要任务 A 的结果 → 必须串行
- **共享写入**：多个任务会改同一个文件 / 同一份状态 → 并行会互相覆盖，必须串行或做隔离
- **需要顺序保证**：步骤本身有先后语义（先建库再上传文档）→ 串行

> avatar-executing 现有的执行循环是**逐步串行**的（每步 writer→reviewer→验证，依赖上一步），那是对的——因为计划里的 step 通常有依赖。并行只用于"这一批 step/任务确实互不依赖"的情况。

## How It Works

1. **拆分**：把工作切成互不依赖的独立单元，每个单元自带完整上下文（子 agent 看不到你的对话，必须把它需要的信息都放进 prompt）。
2. **判独立性**：逐对检查有无依赖、有无共享写入。任一存在 → 该两项不能并行。
3. **并行分发**：把独立单元同时派给多个子 agent（同一批次发出，不逐个 await）。
4. **收敛**：等全部返回后，汇总结果、处理失败项（某个 agent 失败不影响其他，单独重试或降级）。
5. **串行兜底**：并行只在"分发"这一层；有依赖关系的后续步骤仍回到串行。

## Checklist

- [ ] 每个任务确认与其他任务**无依赖**
- [ ] 每个任务确认**不写同一文件/状态**
- [ ] 每个子 agent 的 prompt 自带完整上下文（不依赖对话记忆）
- [ ] 并行分发，不逐个 await
- [ ] 汇总时单独处理失败项，不让一个失败拖垮整批
- [ ] 有依赖的后续步骤已回到串行

- `avatar-executing` Step 3：对标注为独立的一批 step，用本 skill 并行分发 code-writer / avatar-code-writer；有依赖的仍走原串行执行循环。
