# Step 4: 根因分析

## 4.1 分析策略

**有错误码**: 直接查询错误码库
**无错误码**: 症状匹配 + 逐步排查

**分析决策树**:
```
症状: 黑屏
  ├─ 有错误日志?
  │   ├─ 是 → 提取错误码 → 查询错误码库
  │   └─ 否 → 继续
  │
  ├─ 收到 stream_start?
  │   ├─ 否 → 连接/推流问题
  │   │       ├─ 收到 connected? 
  │   │       │   ├─ 否 → 凭据/网络问题
  │   │       │   └─ 是 → 资源未授权 (10120/10121)
  │   │       └─ ...
  │   │
  │   └─ 是 → 播放器问题
  │           ├─ 平台 = Web
  │           │   └─ 播放器分包未加载 (20002)
  │           ├─ 平台 = Android
  │           │   └─ XRTC SDK 缺失 (20002)
  │           └─ 平台 = iOS
  │               └─ Framework 未嵌入
  │
  └─ ...
```

## 4.2 根因分类

**配置错误** (最常见):
```yaml
特征:
  - 凭据拼写错误
  - 参数配置错误
  - 资源未授权

修复难度: 低
修复方式: 修改配置，无需改代码
```

**依赖缺失**:
```yaml
特征:
  - SDK 文件未引入
  - 播放器分包缺失
  - 系统库未添加

修复难度: 中
修复方式: 安装依赖，重新编译
```

**代码缺陷**:
```yaml
特征:
  - 事件监听缺失
  - 错误处理不当
  - 资源未释放

修复难度: 中
修复方式: 修改代码，重新测试
```

**环境问题**:
```yaml
特征:
  - 网络不可达
  - 权限未授予
  - 浏览器不兼容

修复难度: 高
修复方式: 需要用户手动配置环境
```
