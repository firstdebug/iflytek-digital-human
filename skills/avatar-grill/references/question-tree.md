# Grill 问题树

## 1. 原则

问题树不是固定问卷。只有同时满足以下条件的问题才进入当前 `frontier`：

1. 它的前置条件已经成立。
2. 答案仍未知。
3. 不能由工程、平台工具或实际 SDK 产物确定。
4. 不同答案会改变代码、权限、平台写操作、资源选择或验收标准。

每轮把所有 frontier 集中成一组问题。等用户回答整轮后再重新计算。依赖本轮答案的问题放到下一轮。`docs` 咨询在 frontier 为空时直接回答，不生成写操作契约；其他任务才进入执行契约。

## 2. 固定回合格式

每轮按以下格式一次性列出当前全部 frontier，不逐题追问：

```markdown
❓ **Q1** - **<标题>**：<题干，含选项>

➡️ 推荐：<推荐答案>。影响：<会改变哪段执行路径>

---
```

每个问题都必须给出推荐答案和具体影响。工具可查询的事实不提问；不会改变代码、权限、平台写操作、资源选择或验收标准的偏好不提问。

### 完整示例

用户说：“在 `D:/demo` 做一个 Web 虚拟人页面。”工程扫描确认目录为空后，第一轮 frontier 是交互形态、附加能力和资源写操作：

```markdown
❓ **Q1** - **核心交互**：选择文本播报、文本问答、音频驱动、短语音或全双工。

➡️ 推荐：文本问答。影响：决定驱动 API、NLP 链路和验收用例。

---

❓ **Q2** - **附加能力**：选择字幕、动作、透明背景；也可以都不选。

➡️ 推荐：字幕。影响：决定前端事件处理和首帧后的显示验收。

---

❓ **Q3** - **资源写操作**：允许复用工具验证到的已发布场景，还是允许创建并发布新场景？

➡️ 推荐：优先复用已发布场景。影响：决定契约是否授权创建和发布平台资源。

---
```

用户整轮回答：“文本问答，加字幕；优先复用，没有合适的再创建。”随后重新计算 frontier。只有用户选择语音时，下一轮才询问语音操作形态和麦克风权限；本例未选语音，直接把 `voice_interact`、`full_duplex` 和音频驱动写入 `features.excluded`，不追问是否顺便添加。

## 3. 事实与决策

### 必须由工具或工程确定

- 固定 WS URL 和控制台入口
- 当前工程的平台、SDK 版本和已实现能力
- appId 列表、appType、授权和凭据可用性
- sceneId、sceneType、所属 appId、发布状态
- avatarId、vcn、模型、知识库和资产授权
- SDK 下载物、API 签名和构建工具版本
- 服务端口、运行状态、首帧和交互证据

这些内容不得作为用户问题。工具需要登录时，只询问用户完成扫码或授权动作。

### 必须由用户决定

- 目标是咨询、创建、修改、排障还是验证
- Web、Android、iOS、WebAPI、官方模板或直播
- 新项目路径或要修改的现有工程
- 文本播报、文本问答、音频驱动、短语音或全双工
- 字幕、动作、透明背景、自定义形象和声音
- 语音的操作形态
- 是否复用工具验证过的应用、场景、模型和知识库
- 会改变数据的平台写操作和验收标准

## 4. 根问题

只有用户目标宽泛时询问：

```markdown
❓ **Q1** - **交付类型**：选择官方 Web 模板链接、数字人直播项目、Web/Android/iOS SDK 工程、后端 WebAPI 接入，或修改/排查已有项目。

➡️ 推荐：需要最快得到可访问页面时选择官方 Web 模板；需要自定义工程能力时选择对应 SDK 工程。影响：决定 `task.kind`、后续问题分支、平台写操作和验收门禁。

---
```

用户已明确结果时不再问。

## 5. SDK 工程分支

前置：用户选择 SDK 工程或现有 SDK 工程。

当前 frontier 可包含：

- 目标平台；已有工程则由扫描确定。
- 项目路径；用户未指定且需要新建时才问。
- 核心交互：纯播报、文本问答、音频驱动、短语音、全双工。
- 附加能力：字幕、动作、透明背景、自定义背景。
- 是否复用已验证资源，或者允许在已选 appId 下创建并发布新接口场景。
- 验收标准：至少构建成功、连接、首帧和所选交互；用户可增加业务验收条件。

### 语音子树

仅在用户明确选择短语音或全双工后激活：

- 短语音：按住说话、点击开始/停止、自动 VAD。
- 全双工：持续监听、实时打断和回声处理。
- 是否允许新增麦克风权限和对应 UI。

未确认时，`voice_interact`、`full_duplex` 和麦克风权限必须进入 `features.excluded`。

### 透明背景子树

仅在用户选择透明背景后激活：

- 自定义背景如何提供。
- 验收是否需要在目标浏览器或真机检查合成效果。

协议不是用户问题。透明背景强制 `xrtc`，由契约规则自动写入。

## 6. Web 模板分支

前置：用户选择官方模板。

- 模板类型：大屏、Web 客服、Web 弹窗、H5 对话、H5 通话。
- 应用名称和用途。
- 从工具列出的 `appType=2` 应用中选择；不要让用户手输未知 appId。
- 是否更换背景、形象、发音人、引导词和识别语言。
- 是否立即发布；域名和有效期仅在需要时询问。

模板 ID 由模板类型映射，不让用户记数字。

## 7. 直播分支

前置：用户选择数字人直播。

- 项目名称和用途。
- 从工具验证过的应用中选择。
- 使用平台默认形象/发音人还是从实际资产列表选择。
- 商品、分镜和脚本内容；未知时可先使用明确标记的最小内容。
- 是否立即发布并打开配置页面。

## 8. WebAPI 分支

前置：用户选择不用 SDK 的后端 WebAPI。

- 目标语言和现有服务路径。
- 需要的请求：文本驱动、文本交互、音频驱动、事件监听等。
- 是否需要可运行 demo、集成到现有后端或仅查看报文。
- 资源复用或允许创建接口场景。

签名算法、WS URL 和协议字段由内置资料确定，不询问用户。

## 9. 模型与知识库分支

### 模型

- 使用官方模型还是自有 OpenAI 兼容模型。
- 目标场景和模型选择，候选必须来自工具查询。
- 自有模型的名称、model、base URL；密钥只通过安全交互输入。
- 是否绑定并立即发布。

### 知识库

- 新建还是复用工具列出的知识库。
- 文档路径、分类和拆分策略。
- 关联到哪个已验证场景。
- 调用链顺序。
- 是否立即发布。

绑定自有模型时，调用链第二段由工具验证到的 `nlpType` 决定，例如 `docqa,openai`，不让用户猜。

## 10. 配置、排障与验证分支

### 配置

- 目标工程或场景。
- 要改变的配置和目标值。
- 影响现有行为时，确认是否接受影响。

### 排障

优先读取日志、错误码、关闭码、平台查询和运行证据。只询问工具无法获得的复现步骤、期望行为和最近改动。

### 验证

扫描已有证据后，只询问目标工程和用户额外验收条件。构建、连接、首帧、目标交互和安全扫描属于固定门禁，不作为可选问题。

## 11. 结束条件

满足以下条件时 frontier 清空：

- 任务类型和目标位置明确。
- 启用能力与排除能力明确。
- 所有会改变实现的用户决策已有答案。
- 所有关键平台事实有工具来源或明确标记为待执行时验证。
- 验收条件可操作。

然后只做一次共同理解确认，不继续扩展问题。
